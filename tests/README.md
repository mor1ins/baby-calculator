# Сквозные проверки системы

Проект Playwright `integration` запускает собранный React-интерфейс в Chromium и работает с настоящим HTTP API и PostgreSQL из Docker Compose. Ответы API, конфигурация приложения и база не подменяются. Каждый тест создаёт отдельный аккаунт. API используется для подготовки истории и проверки сохранённых данных; проверяемые пользовательские действия выполняются в браузере.

Проект `visual` содержит отдельные проверки макета и темы с фиксированными ответами API. Они не считаются интеграционным покрытием.

## Запуск

Из корня репозитория:

```sh
BABY_REGISTRATION_ENABLED=true FRONTEND_REGISTRATION_ENABLED=true docker compose up --build -d
cd tests
npm ci
npx playwright install --with-deps chromium
npm run test:integration
```

`npm test` запускает оба проекта, `npm run test:visual` — только визуальные проверки. Для другого адреса задайте `BABY_E2E_URL`; для установленного Chrome — `BABY_CHROME_PATH`. Адрес по умолчанию: `http://localhost:8080`. Используйте отдельное тестовое окружение: тесты создают аккаунты и записи, а административный сценарий блокирует созданного им пользователя.

Для административного теста по умолчанию используется локальный `docker compose exec`. Альтернативу можно указать через `BABY_ADMIN_COMMAND` как JSON-массив аргументов команды создания администратора.

## Покрытие

| Сценарий | Проверка |
| --- | --- |
| Доступность событий в любом состоянии дневника | `zz-event-access.spec.js`: новый день, бодрствование, укладывание, дневной сон, ночной сон, ночное бодрствование, продолжающаяся вчерашняя ночь и история. Добавление через форму, редактирование каждой сохранённой записи в ленте (включая активные), границы дневного бодрствования, сохранение после перезагрузки и сохранение текущего режима |
| Регистрация, вход, неверный пароль, выход | `diary.spec.js`: действия через формы и восстановление сессии |
| Дневной сон и заметки | `diary-lifecycle.spec.js`: создание, исправление, удаление, пересчёт итогов, перезагрузка |
| Некорректные границы и пересечение снов | `diary-lifecycle.spec.js`: ошибка, сохранение введённых значений, отсутствие частичной записи |
| Одновременное редактирование | `diary-lifecycle.spec.js`: две настоящие вкладки, защита от незаметной перезаписи |
| Графики | Создание и выбор по умолчанию; редактирование, архив и восстановление; неизменность исторического снимка |
| Профиль родителя и малыша | Сохранение имени малыша и родителя, часового пояса; сохранение времени старых записей |
| Укладывание | `report-settling.spec.js`, `night-wakings.spec.js`: старт, перезагрузка, завершение без сна, переход ко сну, изменение границ |
| Переход дня в ночь | `night-day-continuity.spec.js`: дневная лента сохраняется после начала ночи и перезагрузки |
| Ночь через полночь | `overnight-home.spec.js`: активный сон доступен утром без переходов на прошлую дату |
| Ночные бодрствования | Старт/окончание таймером, ручное добавление, редактирование и удаление в ленте, график и исключение из итогов сна |
| Завершение ночи | Матрица до/после полуночи × без бодрствования/снова уснул/ещё бодрствует; правильное начало участка и утренняя граница |
| История и утро | `morning.spec.js`, `diary.spec.js`: предыдущая ночь, заметки на исходной дате, утренние показатели |
| Календарные границы ритма | `zz-rhythm-calendar.spec.js`: ночное бодрствование после полуночи только на своей дате; пересечение полуночи делится между строками; шкала и полосы остаются внутри календарных суток |
| Статистика и экспорт | `report-settling.spec.js`: вкладки, мобильная ширина, реальное скачивание и чтение Excel, даты выбранного периода, заметки всегда в личном файле |
| Публичный отчёт | Отдельный анонимный браузер, Excel без личных заметок, отзыв ссылки |
| Изоляция семей | Отдельный аккаунт не видит записи и не может изменить чужой сон |
| Администратор | `night-admin.spec.js`: дневник только для чтения и прекращение доступа после блокировки |

Проверки не используют автоматические повторные запуски тестов. Единственное исключение на этапе подготовки: при ответе 429 на регистрацию вспомогательного аккаунта ожидается минута и повторяется только регистрация. Это учитывает реальный лимит 15 регистраций в минуту с одного IP; защиту сервера тесты не отключают. В CI `test.only` запрещён. При ошибке сохраняются скриншот, трассировка и HTML-отчёт. Сквозные и визуальные проверки выполняются в PR и перед выкладкой dev; ошибка останавливает выкладку. Артефакты неудачного запуска доступны в GitHub Actions.

Этот набор проверяет основные пользовательские сценарии на уровне всей системы. Контрактные, конкурентные и остальные граничные случаи backend дополнительно проверяются в `backend/tests` на PostgreSQL.
