# Тише — дневник сна малыша

Рабочий локальный прототип: React/FastAPI/PostgreSQL. Регистрация, личный дневник, несколько графиков и снимки на даты, сон и вычисляемое бодрствование, заметки, ночные отметки, история, метрики и прогноз. Администратор просматривает данные и управляет блокировкой; учетная запись admin создается вручную в БД.

## Запуск

Нужны Docker и Docker Compose. Из корня репозитория:

```sh
cp .env.example .env
docker compose up --build -d
```

Открыть **http://localhost:8080** и зарегистрироваться. API работает с того же адреса; PostgreSQL наружу не опубликован. Миграции применяются отдельным контейнером до запуска backend. После первоначальной сборки можно запускать `docker compose up --no-build -d`.

Для доступа со смартфона подключите оба устройства к одной локальной сети. В `.env` задайте `APP_BIND_ADDRESS=<локальный IP компьютера>` и `APP_ORIGIN=http://<локальный IP компьютера>:8080`, затем выполните `docker compose up --no-build -d`. На обоих устройствах используйте адрес из `APP_ORIGIN`. На macOS IP Wi-Fi обычно показывает `ipconfig getifaddr en0`; при смене IP обновите `.env` и повторите запуск.

```sh
docker compose ps
docker compose logs --tail=100 backend
docker compose stop
```

База хранится в volume `baby-local_postgres-data`; остановка контейнеров сохраняет записи. `docker compose down -v` удалит локальную базу. Импорта из старого калькулятора и резервного копирования в прототипе нет.

Если Docker Desktop зависает при получении метаданных образов, проверьте его credential helper и BuildKit. Для уже загруженных базовых образов доступен локальный обход: `DOCKER_BUILDKIT=0 docker compose build`, затем `docker compose up --no-build -d`. Настройки учетных данных Docker проект не изменяет.

## Первый день

1. В «Мои графики» создать шаблон и при необходимости выбрать его по умолчанию.
2. Чтобы задать утреннюю границу, записать предыдущую ночь: день цикла — предыдущая дата, начало/конец с датами, окончательное утреннее пробуждение — «Да».
3. На нужной дате выбрать график; затем отмечать сон. Бодрствование вычисляется автоматически.
4. Во время ночи «Проснулся / заплакал» сохраняет отметку без завершения сна. «Утренний подъём» завершает ночь. Для измеренного ночного разрыва использовать исправление сна без завершения ночи, затем новый отрезок ночного сна того же цикла.

Неизвестные метрики показаны «—». Без утренней границы прогноз не строится. Исправление сна не удаляет заметки: потерявшие интервал заметки можно перепривязать. При конфликте версии введенные данные остаются в форме; нужно сверить обновившуюся запись. Редактирование графика позволяет применить изменения к сегодня или только к последующим новым дням; ранее сохраненные снимки остаются прежними.

## Создание администратора

Это ручная операция в базе, а не публичная регистрация:

```sh
docker compose exec backend .venv/bin/python create_admin.py --email admin@example.com
```

Команда спросит пароль без вывода на экран. Создает новую учетную запись только с ролью `admin`; существующих пользователей не изменяет. Вход через обычный экран, затем ссылка «Открыть список пользователей». Администратор не получает права редактировать чужие дневники.

## Разработка и проверки

Инструкции отдельных частей: [backend](backend/README.md), [frontend](frontend/README.md), [доставка и эксплуатация](deploy/README.md). Контракт: [api/README.md](api/README.md), [OpenAPI](api/openapi.yaml). Решения и статус задач: [PLAN.md](PLAN.md).

```sh
make -C backend setup check
cd frontend && npm ci && npm run check
```

Для интеграционных тестов backend нужен отдельный PostgreSQL с правом CREATEDB. Тесты создают и удаляют собственные базы; рабочую базу они не очищают:

```sh
BABY_TEST_DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/tests make -C backend test-integration
```

Для E2E запустить Compose, затем:

```sh
cd tests
npm ci
npx playwright install chromium
npm test
```

E2E создают тестовых пользователей с уникальными email, графики и записи в запущенном приложении. Включен сценарий ручного создания admin через контейнер. Для другого адреса задать `BABY_E2E_URL`; для установленного Chrome — `BABY_CHROME_PATH`. `BABY_ADMIN_COMMAND` позволяет задать JSON-массив команды ручного создания admin при запуске без Compose.

## Границы прототипа

Один дневник на пользователя, русский интерфейс, без совместного доступа, уведомлений, восстановления пароля и медицинских рекомендаций. Dev/prod рассчитаны на один VPS. Workflow и серверная конфигурация подготовлены; конкретный VPS, домен, сертификаты и repository secrets еще нужно настроить перед внешним выпуском. Локальный запуск от них не зависит.

## Закрытое семейное использование

Публичная регистрация по умолчанию отключена независимо на двух уровнях.
В корневом `.env` (для VPS — в `.env` окружения):

```env
BABY_REGISTRATION_ENABLED=false
FRONTEND_REGISTRATION_ENABLED=false
```

Первый флаг блокирует операцию регистрации на backend с HTTP 403
`registration_disabled`, даже при прямом запросе к API. Второй скрывает ссылку
на регистрацию и перенаправляет `/register` на `/login`. Существующие аккаунты
и вход продолжают работать. Для включения регистрации нужны оба флага `true`.
Применение изменений: `docker compose up -d --no-deps backend frontend`.
Фронт читает конфиг при загрузке страницы; после изменения обновите страницу.
Docker генерирует `/config.js` при старте контейнера, пересборка для смены флага
не нужна. При разработке через Vite настройка `registrationEnabled` находится
в `frontend/public/config.js`; backend получает переменную окружения отдельно.

Локально используется HTTP, в том числе в домашней сети. HTTPS включается на VPS:
сертификаты и перенаправление HTTP → HTTPS обслуживает Nginx хоста по
`deploy/edge.conf.example`, а `BABY_ENVIRONMENT=dev/prod` включает Secure-cookie.
Для серверного окружения `PUBLIC_ORIGIN` должен быть точным HTTPS-адресом сайта.

E2E-сценарии регистрации запускайте только на отдельном тестовом окружении
с обоими флагами `true`; CI включает их явно. Отключение публичной регистрации
не мешает ручному созданию администратора через `deploy/create_admin.py`.

Известные проблемы производительности и направления исправления перечислены
в [PLAN.md — известные проблемы](PLAN.md#известные-проблемы).
